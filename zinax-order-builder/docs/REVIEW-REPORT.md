## 1. هدف پروژه (بدون تغییر)

ابزار ثبت سفارش تولید درب کابینت/MDF/ممبران PVC. **این یک اپلیکیشن CNC/CAM نیست.** محصول همچنان فقط: Production CSV، Order PDF، Proforma Invoice PDF اختیاری، Order Project JSON، و Settings/Customers/Catalog JSON.

---

## 2. نتیجه‌ی امکان‌سنجی Tauri: **قابل اجرا و تأیید شده**

به‌جای Electron (سنگین‌تر) یا بازنویسی کامل با PySide6 (تکرار منطق کسب‌وکار)، از **Tauri v2** استفاده شد چون همان اپ React/TypeScript و همان `src/core/` را بدون هیچ تغییری بازاستفاده می‌کند.

### چک‌لیست امکان‌سنجی (همه روی این محیط لینوکسی تست و تأیید شد)

| سؤال | نتیجه |
|---|---|
| آیا build ویژن (Vite) داخل Tauri کار می‌کند؟ | ✅ آره، بدون تغییر |
| آیا اپ به‌صورت دسکتاپ واقعی باز می‌شود؟ | ✅ آره — باینری واقعی ساخته و اجرا شد، همان UI (Dashboard/New Order/...) داخل پنجره‌ی native رندر شد |
| آیا `@react-pdf/renderer` داخل WebView کار می‌کند؟ | ✅ آره — همان PDF متنی ۴.۵ کیلوبایتی، دقیقاً مثل نسخه‌ی وب |
| آیا دانلود CSV/PDF/JSON داخل WebView کار می‌کند؟ | ⚠️ **نه به‌صورت قابل‌قبول** — روش قدیمی (کلیک روی لینک Blob) بدون خطا اجرا می‌شد ولی فایل را **بی‌صدا** در پوشه‌ی کاری اپ ذخیره می‌کرد، بدون دیالوگ و بدون این‌که کاربر بداند فایل کجا رفت. **رفع شد** (بخش ۳). |
| آیا localStorage بین اجراهای اپ باقی می‌ماند؟ | ✅ آره — تأیید شده با فایل واقعی روی دیسک (`~/.local/share/com.zinax.orderbuilder/localstorage/...`) که بعد از بستن و باز کردن دوباره‌ی اپ باقی ماند |
| آیا دیالوگ فایل لازم است؟ | ✅ آره — دقیقاً همین چیزی بود که کم بود؛ اضافه شد |
| مشکل مسیر/دسترسی ویندوز؟ | ⚪ روی این محیط (لینوکس) تست نشد — نیاز به تأیید روی ماشین ویندوز واقعی یا CI |

## 3. باگ واقعی که پیدا و رفع شد: ذخیره‌ی بی‌صدای فایل

قبل از این فاز، دکمه‌ی «Export CSV» داخل اپ دسکتاپ فایل را **بدون هیچ دیالوگ و بدون اطلاع کاربر** در پوشه‌ی اجرای برنامه می‌نوشت — یک مشکل UX واقعی برای اپ دسکتاپ. راه‌حل: دو adapter جدید که فقط لایه‌ی ذخیره‌سازی فایل را جدا می‌کنند، بدون تغییر در `src/core/` یا کامپوننت‌های صفحه:

```
src/desktop/
├── desktopEnvironment.ts   # isDesktopRuntime() — تشخیص Tauri با isTauri()
└── desktopFileAdapter.ts   # دیالوگ Save واقعی Tauri + نوشتن فایل با fs plugin

src/web/
├── webEnvironment.ts       # isDesktopRuntime() → false (برای تقارن)
└── webFileAdapter.ts       # همان دانلود Blob مرورگری قبلی، بدون تغییر
```

`src/lib/download.ts` (لایه‌ی مشترک) بین این دو runtime سوییچ می‌کند — کامپوننت‌های صفحه هیچ‌وقت مستقیماً API تاوری صدا نمی‌زنند، و `src/core/` هم اصلاً از این موضوع خبر ندارد. تأیید زنده روی باینری واقعی: کلیک روی «Export Production CSV» یک دیالوگ native با عنوان دقیق **«Save File»** باز کرد (قبلاً هیچ دیالوگی باز نمی‌شد).

نکته: سمت **خواندن/Import** (`<input type="file">`) از قبل بدون هیچ تغییری داخل Tauri درست کار می‌کند — چون input فایل، پیکر بومی سیستم‌عامل را باز می‌کند؛ فقط سمت **نوشتن/Save** نیاز به adapter داشت.

## 4. شل دسکتاپ (`src-tauri/`)

| تنظیم | مقدار |
|---|---|
| نام اپ / عنوان پنجره | ZINAX Order Builder |
| اندازه‌ی پیش‌فرض | 1440×900 |
| حداقل اندازه | 1200×760 |
| تم | Light |
| بک‌اند/لاگین/auto-update/cloud sync | هیچ‌کدام — طبق دستور اضافه نشد |
| پلاگین‌های Rust | `dialog` (Save/Open)، `fs` (خواندن/نوشتن فایل)، `log` |

نتیجه‌ی واقعی `npm run desktop:build` روی این محیط: سه باندل واقعی و قابل‌نصب ساخته شد — `.deb`، `.rpm`، و `.AppImage` (برای ویندوز، معادلش `.msi`/`.exe` است که نیاز به بیلد روی ماشین ویندوز یا GitHub Actions دارد — بخش ۶).

## 6. چیزهایی که هنوز ساخته **نشده** / محدودیت‌های شناخته‌شده

1. **باینری واقعی ویندوز (.msi/.exe)** — روی این محیط لینوکسی ساخته نشد. توصیه: GitHub Actions با runner `windows-latest` و اکشن رسمی `tauri-action`. کد Rust/تنظیمات به لحاظ پلتفرم خنثی هستند، پس این کار باید بدون تغییر کد جدی انجام شود.
2. **تست کامل تعاملی دیالوگ‌ها روی دسکتاپ واقعی** — روی این محیط (بدون window manager) دیالوگ‌های native به‌صورت خالی/بدون تم رندر می‌شوند و بستن اجباری پنجره‌ها می‌تواند کل اپ را کرش کند؛ این محدودیت محیط تست است نه باگ اپ. باز شدن دیالوگ (با عنوان تأیید‌شده) و مسیر لغو (بدون نوشتن فایل) تأیید شد، ولی یک پاس کامل «تایپ نام فایل و کلیک Save» روی یک دسکتاپ واقعی (ویندوز یا لینوکس با WM) هنوز لازم است.
3. **آیکون‌های اپ** — هنوز آیکون‌های پیش‌فرض Tauri هستند، نه برندینگ ZINAX.
4. نسخه‌ی Windows هنوز بک‌اند/لاگین/آپدیت خودکار ندارد — طبق دستور این فاز عمداً اضافه نشد.
5. محدودیت‌های قبلی (بدون تغییر): چندزبانه/RTL واقعی هنوز جای‌گیر است؛ مکانیزم انتخاب مشتری فقط یک dropdown است.
