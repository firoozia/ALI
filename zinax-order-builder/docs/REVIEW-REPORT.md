## 1. هدف پروژه (بدون تغییر)

ابزار ثبت سفارش تولید درب کابینت/MDF/ممبران PVC. **این یک اپلیکیشن CNC/CAM نیست.** محصول همچنان فقط: Production CSV، Order PDF، Proforma Invoice PDF اختیاری، Order Project JSON، و Settings/Customers/Catalog JSON. `src/core/` هیچ تغییری در این فاز نکرد.

## 3. چک‌لیست QA بازنویسی شد — برای یک تستر غیرمهندس

`docs/WINDOWS_DESKTOP_MANUAL_QA_CHECKLIST.md` کامل بازنویسی شد تا کسی که برنامه‌نویس نیست هم بتواند دنبالش کند — زبان ساده، بدون هیچ اصطلاح فنی. حالا دقیقاً این ۳۰ مرحله را پوشش می‌دهد (قبلاً ۲۲ مرحله بود):

- نصب از MSI، و اگر MSI مشکل داشت، نصب از EXE به‌جایش
- تأیید نام اپ، آیکون اپ، و اندازه‌ی پنجره (۱۴۴۰×۹۰۰ پیش‌فرض، حداقل ۱۲۰۰×۷۶۰)
- ساخت سفارش خالی، افزودن مشتری، کد درب، رنگ PVC، و یک ردیف سفارش
- همه‌ی Export ها (CSV، Order PDF، Invoice PDF، JSON سفارش) با تأیید صریح UTF-8 بودن متن CSV و قابل‌انتخاب‌بودن متن PDF
- بستن و بازکردن دوباره‌ی اپ برای تأیید persistence
- بازکردن فایل JSON سفارش ذخیره‌شده
- لغو دیالوگ Save و تأیید این‌که هیچ فایلی ساخته نمی‌شود
- تست کامل بدون اینترنت
- **جدید:** حذف نصب (Uninstall) و نصب دوباره، و یادداشت رفتار بعد از نصب مجدد
- **جدید:** یادداشت این‌که هشدار SmartScreen ویندوز دیده شد یا نه (انتظار می‌رود دیده شود چون نصب‌کننده هنوز امضا نشده)

## 4. دو فایل جدید برای گردش‌کار QA

- **`docs/WINDOWS_DESKTOP_QA_RESULT_TEMPLATE.md`** — فرم قابل‌پرکردن برای تستر: مدل لپ‌تاپ، نسخه‌ی ویندوز، MSI یا EXE، آیا SmartScreen دیده شد، نتیجه‌ی هر Export (بله/خیر)، persistence (بله/خیر)، حالت آفلاین، لیست باگ‌ها، اسکرین‌شات‌ها، و نتیجه‌ی نهایی (Pass / Pass with issues / Fail).
- **`docs/RELEASE_NOTES_DRAFT.md`** — فقط برای تست داخلی. شامل: این اپ چیست/چی نیست، پنج خروجی واقعی، محدودیت‌های شناخته‌شده (نصب‌کننده امضا‌نشده، متادیتای publisher/copyright placeholder، آیکون موقت، بدون عربی/RTL، بدون بک‌اند/لاگین)، و یک بند صریح: **«QA دستی قبل از انتشار الزامی است.»**

## 5. بهبودهای کوچک UX (بدون تغییر منطق)

| قبل | الان |
|---|---|
| لغو دیالوگ Save → هیچ toast (سکوت کامل) | لغو دیالوگ Save → toast خاکستری خنثی: «Save cancelled — no file was saved.» (نه success، نه error) |
| دکمه‌ی غیرفعال «Export Proforma Invoice PDF» بدون توضیح چرا غیرفعال است | همان دکمه حالا با نگه‌داشتن ماوس (tooltip) دقیقاً می‌گوید کدام خطای اعتبارسنجی مانع export است |
| `README.md` هنوز می‌گفت «UI Prototype، Export ها فقط mock» (باقی‌مانده از Phase 1) | `README.md` کامل به‌روزرسانی شد تا واقعیت فعلی (Export های واقعی، نسخه‌ی دسکتاپ، صفحات واقعی) را نشان دهد |

هیچ تغییری در `src/core/`، schema های CSV/PDF/JSON، یا لایه‌ی PDF انجام نشد — همه‌ی ۵۱ تست قبلی بدون تغییر پاس می‌شوند.

## 7. چیزهایی که هنوز ساخته **نشده** / محدودیت‌های شناخته‌شده

1. **تست دستی روی سخت‌افزار ویندوز واقعی هنوز انجام نشده** — این دقیقاً همان چیزی است که این فاز برایش آماده شده؛ قدم بعدی واقعی، اجرای همین چک‌لیست توسط یک انسان روی یک ویندوز واقعی است.
2. بدون امضای دیجیتال (SmartScreen احتمالاً هشدار می‌دهد) — طبق دستور عمداً اضافه نشد.
3. متادیتای publisher/copyright و آیکون هنوز placeholder هستند.
4. محدودیت‌های قبلی بدون تغییر: بدون عربی/RTL واقعی، بدون بک‌اند/لاگین/cloud sync.
